# Articles to Anki

Простой Python-сайт создаёт профиль с обязательным паролем от 12 символов,
хранит PDF и APKG отдельно, показывает PDF с нативным выделением слов,
после кнопки «Добавить» переводит и сохраняет жёлтые хайлайты, отмечает статьи
прочитанными и выгружает только новые карточки. При экспорте
APKG старые карточки и их расписание сохраняются, новые добавляются без дублей.
Основной поток может синхронизировать карточки напрямую через AnkiWeb; APKG
остаётся резервным способом.
Контексты одного смыслового кластера собираются в одну карточку; разные
значения одного написания остаются разными карточками. Новые карточки получают стабильный ID в тегах Anki;
старые сопоставляются по типу, слову и контексту предложения. При загрузке APKG
сайт только читает и сопоставляет её содержимое. Старые типы заметок не
переписываются; semantic-заметки обновляют только поля по стабильному ID,
сохраняя карточку и её расписание. Успешно собранная APKG
становится базой следующего экспорта, и её можно скачать повторно даже без
новых карточек.

## Смысловые карточки

Новое выделение сначала нормализуется: Unicode приводится к канонической форме,
регистр понижается, переносы и шумовая пунктуация удаляются, а пробелы, дефисы и
апострофы сохраняются. Затем RapidFuzz ищет не более пяти кандидатов только по
лидерам существующих кластеров. Каждая semantic-карточка и есть кластер: её `id`
служит стабильным `cluster_id`, а `target` — лидером. Поэтому омонимы могут иметь
одинаковых лидеров и разные ID.

`deepseek/deepseek-v4-flash-0731:nitro` получает кандидатов, их ID, лидеров и до
пяти уникальных хайлайтов с контекстами. Один strict JSON-ответ выбирает ID
существующего кластера либо явный `new_cluster`, создаёт лидера для нового
кластера и обогащает карточку. Включён reasoning `low`; лимит ответа 16 000 токенов,
чтобы reasoning не обрезал JSON. Формы и дериваты с общим смысловым ядром могут
объединяться: `acquired/acquisition` образуют кластер `acquire`. Омонимы и разные
учебные значения остаются раздельными: `train` («поезд») и `train`
(«тренироваться») имеют одинаковое написание лидера, но разные `cluster_id`.
Ответ выбирается вместе с контекстом, поэтому карточка показывает нужную форму,
а не только лидера. Карточки используют отдельный тип
заметок `Anki Papers Semantic`; старые `Anki Papers` и их расписание не
изменяются.

Для `direction::recall` DeepSeek отдельно оценивает догадки для каждого
контекста. Сначала модель собирает широкие списки естественных подстановок и
близких по смыслу слов, затем выбирает короткие высокоточные списки для
карточки. Служебные brainstorm-списки, источник контекста и другие атрибуты на
карточке не показываются; пересекающиеся итоговые подсказки не дублируются.

Дополнительные контексты для повторения берутся только из реальных предложений
загруженных статей. Кроме точных вхождений находятся словоформы и дериваты
(impair → impaired/impairment) через стемминг Porter и нечёткое сравнение, после
чего семантическая модель одобряет лишь предложения, тренирующие именно это
значение карточки; без ключа API работает консервативный лексический отбор.
Повторное выделение слова, уже покрытого контекстом карточки, переводится с
учётом контекста и не создаёт ни новой карточки, ни дубля контекста.

Автоматический поиск по ar5iv не используется: DuckDuckGo не предоставляет
поддерживаемый API органической выдачи, а Brave требует отдельный ключ и
платёжный профиль. Это исключает нестабильный scrape и скрытый fallback.
PDF с настоящими Highlight-аннотациями скачивается из библиотеки. При pinch
zoom видимые страницы перерисовываются с повышенным разрешением.

При загрузке PDF сайт в фоне импортирует уже существующие хайлайты, заменяет
нативные Highlight-аннотации своими единообразными хайлайтами и готовит
карточки. Исходный PDF сохраняется отдельно. Нативные аннотации и отдельные
слои разметки SPen удаляются из рабочей копии; цвет, уже сведённый с растровым
изображением самой страницы, распознаётся, но безопасно стереть его нельзя.

Удаление карточки на главной странице или хайлайта в читалке — одна операция:
хайлайт исчезает во всех представлениях и не импортируется повторно при
последующей обработке статьи.

## Веб-сайт

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
anki-papers-web --host 0.0.0.0 --port 8000
```

Сайт откроется на `http://localhost:8000`. Production запускает web только на
`127.0.0.1:8000`, а публичный адрес обслуживает Caddy:
`https://151-241-221-199.sslip.io`. SQLite, PDF, APKG и зашифрованные зеркала лежат в
`data/`; этот каталог исключён из Git. Для постоянного запуска используется
Waitress и отдельный sync-worker; Redis, Celery, Docker и внешняя база не нужны.

Быстрый перевод полностью локальный и офлайн. Слово ищется в
англо-русском FreeDict/WikDict (62 181 заголовок, CC BY-SA) — части речи и
переводы из словарной статьи. Словоформы (went, children, acquired, better…)
нормализуются через WordNet: собираются все первоисточники слова по всем
частям речи, и переводы всех найденных форм агрегируются. Если словарь не
нашёл слово (или словоформу), перевод не отдаётся — словарь неполон. Сетевых
переводчиков нет. Установить закреплённый и проверяемый по контрольной сумме
словарь и корпус WordNet:

```bash
.venv/bin/python scripts/install_quick_dictionary.py --data-dir data
```

Production deploy обновляет словарь автоматически. Файлы лежат в
`data/dictionaries/eng-rus/` и `data/nltk_data/` и не попадают
в Git.

## AnkiWeb sync

Worker — отдельный AGPL-3.0-or-later компонент в `sync-worker/`. MIT web-пакет
не импортирует `anki`; связь идёт только через SQLite jobs. Закреплена версия
`anki==26.5`. Обновлять её нужно отдельным PR после protocol-тестов.

Поток:

1. пользователь повторяет пароль сайта и вводит AnkiWeb ID/password;
2. worker проверяет credentials через `sync_login()` и делает только full download;
3. сайт показывает колоды и preview;
4. после выбора колоды worker сначала скачивает remote changes, сопоставляет
   старые notes, добавляет только отсутствующие `meaning`/`recall`, затем делает
   второй incremental sync;
5. любой mandatory full sync всегда выбирает download. Full upload отсутствует
   в application code.

AnkiWeb ID, password, `hkey` и `collection.anki2` шифруются AES-256-GCM.
Создать production key:

```bash
python -c 'import base64,secrets; print("1:" + base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())'
```

Значение хранится как GitHub Environment Secret `ANKI_CREDENTIAL_KEY` и в
production `.env`. Для ротации сначала добавьте новый ключ через запятую,
например `1:OLD,2:NEW`; worker перешифрует credentials и mirror текущей версией.
Старый ключ удаляется только после успешной синхронизации всех подключённых
профилей.

Локальный запуск worker:

```bash
python -m pip install -e ./sync-worker
anki-papers-sync-worker --data-dir data
```

Старые passwordless-профили активируются только одноразовым claim-кодом:

```bash
anki-papers-admin --data-dir data issue-claim USERNAME
```

Код действует 24 часа и погашается после установки пароля.

## CI/CD на Ubuntu

Workflow `.github/workflows/deploy.yml` на каждый push в `main`:

1. запускает тесты;
2. копирует код по SSH в `~/anki-papers` существующего пользователя;
3. останавливает процессы записи и обновляет `.venv`;
4. сохраняет полный архив данных перед миграцией базы;
5. ставит Caddy, перезапускает web + worker и включает ежедневный backup timer;
6. проверяет HTTPS `/health` и `/health/worker`.

GitHub Actions нужны секреты `SERVER_IP`, `SERVER_USER`, `SERVER_PASSWORD`,
`OPENROUTER_API_KEY`, `APP_SECRET` и
`ANKI_CREDENTIAL_KEY`. Сервисы работают от существующего `SERVER_USER`,
запускаются после reboot и пишут логи в journald:
`sudo journalctl -u anki-papers-web -u anki-papers-sync-worker`. Каталог `~/anki-papers/data/` хранит SQLite,
PDF и APKG; при деплое, рестарте процесса и reboot он не удаляется и не
перезаписывается. Одинаковый `APP_SECRET` сохраняет активные сессии между
рестартами.

CLI извлекает слова и выражения, поверх которых в PDF нарисован жёлтый
маркер, находит целое английское предложение и создаёт два типа карточек:

1. предложение с целевым словом в `<b>жирном</b>` → 2–5 разных русских
   переводов, допустимых именно в этом контексте;
2. то же предложение с русской заменой целевого слова и подсказкой
   «Нельзя использовать: ...» → исходное английское слово.

Если в одном предложении выделено несколько разных слов, для каждого слова
создаётся своя пара карточек. Соседние слова под одним мазком объединяются в
выражение, например `By and large`.

## Как работает извлечение

- PDF рендерится в изображение, а текст извлекается вместе с координатами.
- Нативные PDF-аннотации типа `Highlight` читаются напрямую по их
  `QuadPoints`, поэтому обычное выделение текста распознаётся точно и не
  зависит от оттенка.
- Тёплые жёлтые пиксели сопоставляются с прямоугольниками слов.
- Частичные мазки маркера тоже поддерживаются; мелкий текст внутри цветных
  схем отфильтровывается отдельно.
- Проверка вертикального «разлива» отбрасывает жёлтые блоки исходных схем и
  таблиц, которые не являются мазками маркера.
- Переносы с дефисом склеиваются, пунктуация предложения сохраняется.
- Переводы и подсказки создаёт `deepseek/deepseek-v4-flash-0731:nitro` через OpenRouter.
  Ответ запрашивается в режиме strict `json_schema`; схема генерируется
  Pydantic, проходит response healing и повторно валидируется Pydantic перед
  записью CSV. Модель обязана сначала объяснить выбранное по полному
  предложению значение, затем дать только совместимые с ним переводы.
  Русские поля обязаны содержать кириллицу. Подсказки содержат только естественные
  английские синонимы, которые подставляются без изменения соседних слов; если таких
  вариантов нет, список остаётся пустым.

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
articles-to-anki /Users/matvey/Downloads/v2.pdf --debug
```

По умолчанию цели отправляются по одной, а каждый успешный ответ немедленно
попадает в кеш.
Карточки перемешиваются непосредственно перед записью CSV. Случайное зерно
сохраняется в `run.json`; для воспроизводимого порядка передайте, например,
`--shuffle-seed 42`.

Ключ читается из `.env`:

```dotenv
OPENROUTER_API_KEY=sk-or-v1-...
OPENROUTER_MODEL=deepseek/deepseek-v4-flash-0731:nitro
OPENROUTER_SEMANTIC_MODEL=deepseek/deepseek-v4-flash-0731:nitro
```

`.env` исключён из Git. Для проверки распознавания без API:

```bash
articles-to-anki /path/to/article.pdf --extract-only --debug
```

Результат для `v2.pdf` появится в `output/v2/`:

- `anki_cards.csv` — готовые строки карточек;
- `extracted_targets.json` — найденные слова, предложения и страницы;
- `enrichment_cache.json` — кеш ответов модели для дешёвого перезапуска;
- `debug/` — страницы с зелёными рамками принятых слов и красными рамками
  отфильтрованных жёлтых элементов схем.

## Импорт в Anki

В окне импорта выберите `anki_cards.csv`, оставьте разделитель `Comma`,
включите HTML в полях и сопоставьте `Front`, `Back`, `Tags`. В файле две
перемешанные строки на каждую найденную цель; типы разделяются тегами
`card::meaning` и `card::recall`.

## Настройка чувствительности

Для другого оттенка или менее аккуратного маркера можно начать с порога:

```bash
articles-to-anki article.pdf --min-coverage 0.50 --max-vertical-spill 0.35 --debug
```

Перед генерацией переводов полезно сначала открыть изображения из `debug/`.


## Структура кода

В `src/articles_to_anki/` роли разделены по каталогам:

- `web/` — создание приложения, авторизация, маршруты;
- `storage/` — база, миграции, файлы и зеркала;
- `documents/`, `extraction/` — PDF, выделения и поиск текста;
- `cards/`, `enrichment/` — контексты, карточки и обращения к модели;
- `rebuilding/`, `jobs/` — пересборка колод и фоновые задачи;
- `backups/` — интерфейс хранилища, снимок данных и запуск бэкапа.

`webapp.py`, `extract.py`, `enrich.py`, `rebuild.py` сохраняют точки входа.
В sync-worker транспорт Anki, обработка заметок, состояние очереди и
рендеринг карточек вынесены в отдельные модули. Тесты сгруппированы по роли.
Ограничение 400 строк проверяет `tests/test_structure.py`.
Старый прототип `build_semantic_preview_deck.py`, зависевший от удалённых API,
удалён; актуальная сборка находится в `rebuild.py` / `rebuilding/`.

## Ежедневные бэкапы

`anki-papers-backup.timer` запускается ежедневно в **03:00 UTC** с разбросом
до 15 минут. `Persistent=true` запускает пропущенную задачу после включения сервера.

В продакшене `ANKI_PAPERS_BACKUP_BACKEND=yandex_disk`: архивы загружаются
в `app:/backups` — папку приложения «Anki Papers Backups» на Яндекс Диске.
Перед публикацией проверяются размер и SHA-256, затем временный объект
переименовывается в завершённый архив. Незавершённые загрузки не попадают
в список бэкапов. Старые архивы автоматически не удаляются.

`Dummy` остаётся доступен через `ANKI_PAPERS_BACKUP_BACKEND=dummy`:
он ничего не читает, не создаёт и не отправляет, возвращая статус `skipped`.
Провайдеры реализуют `BackupBackend`: `upload`, `download`, `list_backups`,
`delete`. Удаление в Yandex Disk перемещает архив в корзину.

Проверка последнего бэкапа скачивает его во временный приватный каталог,
сверяет SHA-256 архива и всех файлов manifest, проверяет целостность SQLite.
Рабочие данные при проверке не изменяются:

```bash
.venv/bin/python -m articles_to_anki.backups.verify --data-dir data
# Для конкретной копии добавить --name anki-papers-<timestamp>-<id>.tar.gz
```

При включённом провайдере ежедневная задача от root на время снимка
останавливает только работавшие web/worker, затем запускает их обратно,
в том числе при ошибке. Загрузка архива идёт уже после возобновления сервиса.
Архив включает все постоянные файлы `data/`: базу SQLite (через backup API,
с учётом WAL), PDF, APKG, зеркала, результаты пересборки, словари и кэши.
Исключены временные `anki_work/`, `anki_locks/` и предыдущие `backups/`.
В архиве есть `runtime.env` с ключами восстановления и manifest с SHA-256.
Хранилище должно быть приватным: архив содержит данные пользователей и секреты.
При ошибке задача завершается с ненулевым кодом; временные файлы удаляются.
Провайдер обязан публиковать архив только после полной загрузки.

```bash
systemctl list-timers anki-papers-backup.timer
journalctl -u anki-papers-backup.service
sudo systemctl start anki-papers-backup.service
```

Перед деплоем тот же механизм снимка сохраняет локальный архив в
`data/backups/<timestamp>/backup.tar.gz`, независимо от Dummy.
Локальные копии не защищают от переустановки сервера.
Для восстановления: проверить SHA-256 по manifest, остановить web/worker,
восстановить `data/` по исходному пути из manifest и `runtime.env` как `.env`
с правами `0600`, затем запустить сервисы. Архив содержит секреты, поэтому
распаковывать его следует в приватном каталоге.

### Яндекс Диск: токены и автоматическое продление

Используется `yadisk[sync-defaults]`. OAuth-клиент запрашивает только
`cloud_api:disk.app_folder` — папку приложения. Первый вход требует согласия
владельца аккаунта; последующие продления идут через `refresh_token`.

Локальная настройка (Client ID и Client Secret передать через переменные
`YANDEX_DISK_CLIENT_ID`, `YANDEX_DISK_CLIENT_SECRET`):

```bash
anki-papers-yandex-auth begin
# Открыть выведенную ссылку, разрешить доступ и получить код Яндекса.
anki-papers-yandex-auth complete  # ввод кода скрыт
anki-papers-yandex-auth status
```

Временный PKCE verifier лежит в `.oauth/pending.json`, итоговые реквизиты —
в `.oauth/yandex.json`. Каталог исключён из Git. Файлы имеют права `0600`,
запись атомарная, продление защищено межпроцессной блокировкой.
Не передавайте коды и токены аргументами команд или через логи.

На сервере реквизиты хранятся отдельно от перезаписываемого при деплое `.env`:
`data/oauth/yandex.json`. Переносить файл нужно по SSH с правами `0600` и
каталогом `0700`. Он включается в снимок данных. Таймер
`anki-papers-yandex-token.timer` проверяет срок ежедневно в 02:30–02:35 UTC.
Продление происходит раз в 90 дней или раньше, если срок жизни короче;
каждый новый refresh token сохраняется вместе с access token. При сетевой
ошибке прежний файл остаётся целым, systemd-задача завершается с ошибкой и
следующий запуск повторяет попытку. Без файла задача безопасно пропускается.
После отзыва доступа или истечения refresh token нужен повторный вход.

```bash
systemctl list-timers anki-papers-yandex-token.timer
journalctl -u anki-papers-yandex-token.service
sudo systemctl start anki-papers-yandex-token.service
```

Yandex Disk backend получает актуальный токен через
`backups.yandex_auth.access_token(path)`, который также проверяет срок перед
использованием. Для загрузки архивов должен быть выбран `yandex_disk`.
