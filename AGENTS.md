# AGENTS.md

Правила для работы с этим репозиторием. Главное — Anki APKG и сборка колод.

## Как правильно настраивать APKG (сборка колод)

Проверено на реальном импорте в Anki (`anki==26.5`,
`collection.import_anki_package`). Любая ручная сборка APKG обязана соблюдать:

1. **GUID заметки — это ключ дедупликации при импорте.** Anki ищет заметку по
   `notes.guid` в целевой коллекции: GUID найден → заметка обновляется на месте
   (в той колоде, где лежит старая карточка) или пропускается, а новая карточка
   НЕ создаётся. GUID, выведенный только из содержимого карточки
   (`sha256(front)`), заставляет повторный импорт «вливаться» в старую колоду:
   свежая колода создаётся, но остаётся пустой.
   → Для каждой новой сборки колоды GUID обязан зависеть от идентичности САМОЙ
   сборки (имя колоды / время сборки). Внутри одной сборки GUID должен быть
   детерминированным (повторный импорт того же файла — идемпотентен).
   Реализация: `_rebuild_guid(front, deck_name)` в `rebuild.py`.

2. **Колоды сопоставляются при импорте ПО ИМЕНИ, не по id.** Пакет с колодой
   "X" попадает в существующую колоду с именем "X" в целевой коллекции или
   создаёт новую. Одинаковые имена в разных сборках — слияние. Имя каждой
   сборки должно быть уникальным (метка времени в `_deck_name`).

3. **Прогресс переносится не GUID-ами, а тегами.** Импорт с
   `with_scheduling=True` восстанавливает расписание на карточках,
   сопоставленных по GUID, в их исходной колоде — никакого переноса между
   колодами он не делает. Перенос расписания между сборками делается
   сервером: старые карточки ищутся по тегам `anki_papers::<card id>` +
   `card::<direction>` в старой коллекции (зеркало AnkiWeb), их состояния
   (`type/queue/due/ivl/factor/reps/lapses`) копируются в новые карточки до
   упаковки. Пустая коллекция-источник = карточки стартуют как новые.

4. **Сборка = самостоятельная колода.** В пакете должна быть одна колода со
   свежим содержимым; остальные колоды источника остаются пустыми (пустая
   колода с совпадающим именем — безвредный no-op). Никогда не переиспользуй
   id чужой колоды для содержимого сборки, если её имя не переименовано.
   Колода сборки НЕ должна иметь id=1: импортёр Anki (`gather.rs`,
   `skip_default`) выбрасывает колоду с id=1 из пакета, когда расписание не
   импортируется (`with_scheduling=False` — выбор десктопа по умолчанию), и
   карточки молча падают в «По умолчанию» целевой коллекции. Сдвиг id=1 → свежий
   делает `_avoid_default_deck_id` в `rebuild.py` (в `col.decks` JSON меняется
   ключ + вложенный `id`, в таблицах — колонка `id`; id не зашит в proto-BLOB
   `common`/`kind`, менять колонку безопасно). Интеграционные тесты должны
   проверять импорт БЕЗ `with_scheduling` — с ним баг не воспроизводится.

5. **Современные коллекции: колоды и типы заметок лежат в отдельных таблицах.**
   Для `.anki21b`/`.anki2` новых версий Anki `col.decks`/`col.models` могут быть
   пустыми JSON, а данные живут в таблицах `decks` (имя в колонке `name`,
   конфиг и human-данные — proto-binary в BLOB-колонках) и `notetypes`.
   Читатели обязаны пробовать оба источника (JSON из `col`, затем таблицы) —
   см. `_deck_names`/`_rebuild_note_type_id`/`_deck_id` в `apkg.py` и
   `rebuild.py`. Вставлять сырые строки в `decks`/`notetypes` нельзя —
   proto-BLOB не воспроизвести руками; пустые карточки-колоды из источника
   можно оставить, если имя переименовано у целевой.

6. **Формат упаковки.** Файл называется `collection.anki21b` только если его
   содержимое сжато zstd (магия `28 b5 2f fd`) — иначе `collection.anki2` с
   сырым SQLite. Детект магии на чтении обязателен. В ZIP всегда кладётся
   `media` со `{}`. `config.nextPos` должен быть выше максимального `due`
   новых карточек, `col.mod` обновляется. Запись `notes.guid` — только
   base64url-безопасные символы (`A-Za-z0-9_-`).

7. **Чистить пакет от мусора источника.** Перед упаковкой пакет очищается от
   старых `notes`/`cards`/`revlog`/`graves` — иначе при импорте «проскочат»
   чужие карточки. Очистка не должна трогать `col`/`decks`/`notetypes`/`config`.

## Тесты

- `pytest -q` — основной набор (без Anki).
- Интеграция с настоящим Anki: `RUN_ANKI_SYNC_INTEGRATION=1 pytest -q
  tests/test_rebuild.py -k "imports or second_deck"` (нужен `anki==26.5`).
  Регрессия «второй пересборки» проверяет, что новая колода импортируется
  рядом с прежней, а чужие карточки не трогаются.
- CI: `pytest -q`, затем `RUN_ANKI_SYNC_INTEGRATION=1 pytest -q
  tests/test_anki_integration.py`; деплой — пуш в `main` через GitHub Actions.

## Деплой

Деплой идёт автоматически по пушу в `main` (workflow `.github/workflows/deploy.yml`:
тесты → копирование кода и `.env` → systemd-сервисы `anki-papers-web`,
`anki-papers-sync-worker`, caddy). После пуша проверяй `gh run list` и
`https://<server>/health`, `/health/worker`. Локально в `data/` лежат `app.sqlite3`,
`uploads/`, `anki_mirrors/*.enc` (зашифрованные зеркала коллекций AnkiWeb) —
это прод-данные, не трогать.
